# Running the gateway

```
go build -o <dir>/ ./cmd/gateway
<dir>/gateway -config <file>
```

`-config` names the gateway's JSON configuration file. The decoder rejects any field not listed below. Simulation is on by default and then needs `domains[].workerBinary` for every domain, so a configuration without `workerBinary` exits 78 until it sets `workerBinary` for each domain or sets `simulation.enabled` to `false`. One gateway runs per `storagePath`: it holds `<storagePath>/gateway.lock`, which holds no data.

The gateway checks every batch it serves against Settlement and marks a domain `INCONSISTENT` when they disagree, but it is not a watcher: it sends nothing to L1, and its only signals are its log and its API (`zeno_getHead` status, `-32003`). By design a `LOCAL` gateway counts a failed check on the executor's read-interface files as the executor's fault, so a hostile or broken worker can mark a healthy domain `INCONSISTENT`; the log names the batch and the cause.

| Field | Type | Notes |
|---|---|---|
| `znndEndpoint` | URL | Required; an absolute `http` or `https` URL of a node serving version-3 momenta. |
| `networkName` | string | Required. |
| `confirmationDepth` | integer | Required; 1 to 1023, no default. |
| `storagePath` | absolute path | Required; the gateway's own store. It may not equal, contain or sit inside any `executorStoragePath`, checked as written, with symlinks resolved, and by file identity, at configuration load and again before a domain boots, because the gateway deletes directories under it. A domain directory that holds `batches/`, `cursor`, `meta.json` or `momentum_hashes/` is refused. |
| `listenAddress` | `IP:port` | Optional; default `127.0.0.1:35999`. The host must be an IP address, never a hostname (`0.0.0.0` listens on every interface); port 0 binds a free port. |
| `allowedOrigins` | array of strings | Optional; default empty, which refuses every browser request. Each entry is an origin exactly as a browser sends it: lowercase `http` or `https` `scheme://host[:port]`, without the default port, a path or a trailing `/`. |
| `simulation.enabled` | boolean | Optional; default `true`. `false` turns `zeno_simulate` off (it answers `-32006`, "simulation is disabled") and needs no `workerBinary`. |
| `simulation.maxGas` | integer | Optional; default 100,000,000, 1 to 1,000,000,000; 0 or absent means the default. The largest `plasmaLimit` a simulated input may carry. |
| `simulation.timeoutMs` | integer | Optional; default 2,000, 1 to 5,000; 0 or absent means the default. The time one simulation has before the gateway kills its simulator. |
| `simulation.maxConcurrent` | integer | Optional; default 2, 1 to 8; 0 or absent means the default. Simulators per domain, so simulations running at once per domain. |
| `simulation.uid` | integer | 1 to 9999. Required as root on Linux with simulation enabled, and ignored elsewhere. 0 and the owner of the resolved `storagePath` (or the gateway's own uid when the path does not exist yet) are refused whenever the field is set. It must be a dedicated uid and gid that own no file the gateway or the executor needs, and it must be able to execute `workerBinary`. The simulator's gid equals its uid, so a system uid such as 6 gets the `disk` group on a host install. |
| `domains` | array | Required, non-empty. |
| `domains[].domainId` | integer | Unique within the file. |
| `domains[].source` | string | `"LOCAL"` (read an executor's directory) or `"REMOTE"` (fetch from other gateways). |
| `domains[].executorStoragePath` | absolute path | Required for `LOCAL`: the executor's `storagePath`, read-only. The gateway reads only `batches/`, `bundles/` and `receipts/` under the domain directory. Absent or `null` for `REMOTE`. |
| `domains[].upstreams` | array of URLs | Required for `REMOTE`, 1 to 8 entries, and refused for `LOCAL`. Each is an absolute `http` or `https` base URL of another gateway, without a query or fragment; a path is kept (`https://host/gw` fetches `https://host/gw/bundles/<daHash>`) and userinfo is sent as basic auth. |
| `domains[].workerBinary` | absolute path | Required for every domain, `LOCAL` and `REMOTE`, while simulation is enabled, and checked whenever given: absolute, an existing regular file, executable. The gateway does not check it against the domain record's `stfSpecHash`, so a binary of another version gives previews that differ from the chain; deploy the executor's own worker binary. |

Exit statuses: 0 on a clean shutdown (SIGINT or SIGTERM, including during boot), 1 when a domain fails to boot (including a `znnd` read that does not answer within 30 s), another gateway holds the lock, or the listener cannot bind or the server stops, 78 on an invalid configuration or command line. 78 also covers a missing `simulation.uid` when the gateway runs as root on Linux with simulation enabled, and a missing `workerBinary` while simulation is enabled. 1 also covers simulation refused as root on Linux because the cgroup v2 memory and cpu limits are off, simulation refused as root on a host that does not separate uids (a `sudo` gateway on macOS), and a failure to seal inherited descriptors or turn non-dumpable; each logs a line naming the cause.

The cache lives in `<storagePath>/<domainId>/snapshots/` and `<storagePath>/<domainId>/index/` (directories it creates 0700, files 0600). The index holds every batch the gateway has checked. At boot it keeps the batches above its finalized batch that still match Settlement or, while pending, the executor's batch record; it removes the first one that does not and every batch above it, and marks the domain `INCONSISTENT` when an accepted batch's entry changed. An index that cannot be opened, or that disagrees with the snapshot or with Settlement's entry for its finalized batch, deletes the cache and rebuilds the domain from batch 0. A cache written by a gateway without the index has no `index/`, so the first boot after upgrading rebuilds every domain from batch 0. Each input's L1 sender is read once from `znnd` (`ledger.getAccountBlockByHash`, checked against the send hash, and accepted only from a user send to the Settlement contract that names the domain) and kept for good, and a batch is served only once every sender is stored. An accepted batch whose input names a send that is not an input of the domain marks the domain `INCONSISTENT`; a pending batch that does so stays unpublished. The kept senders are bounded by the L1 sends to Settlement that name the domain. A rebuild re-reads every sender, one `znnd` round trip per input, so every trigger that deletes the cache costs one round trip per input in the domain's history: an index that cannot be opened, an index that disagrees with the snapshot or with Settlement, and a snapshot whose batch entry is not visible (a lagging node or a raised `confirmationDepth`), which discards the whole cache and the index with it. A gateway log line that says "the index is damaged" while running means the index changed under it; stop the gateway and remove `<storagePath>/<domainId>`, and it rebuilds on the next start. At boot the gateway requires `storagePath` to be a real directory owned by its own uid and sets it to 0700, uses its resolved path from then on, refuses a symlink in the path owned by a user other than root or itself, and refuses to start when any parent of its resolved path is owned by a user other than root or itself, or can be written by another user without the sticky bit, and before it creates or deletes anything in a domain's cache it refuses a symlink or a directory owned by another uid. The gateway creates `storagePath` with `MkdirAll` and resolves it with `EvalSymlinks` before its ownership walk, and the walk of the resolved path refuses a link planted between those steps when it leads to a directory another user owns. Run the gateway as its own non-root uid. When the gateway first catches up after boot, it saves a snapshot of the finalized state; after that it saves at most one every 10 minutes while batches finalize, and each save deletes the older ones. A restart rebuilds from the executor's bundles the batches finalized since the last snapshot, about 10 minutes' worth while saves succeed. A clean shutdown saves no snapshot, so a restart after one also rebuilds those batches. At boot it checks the newest snapshot's root against that batch's `postStateRoot` in Settlement at the confirmed height; a mismatch, an invisible entry, or a snapshot it cannot open deletes the cache and rebuilds the domain from batch 0. A node that has not synced past the snapshot's batch, or a raised `confirmationDepth` that hides its entry, discards the cache. A `znnd` error or timeout at boot never deletes the cache. Deleting a domain's cache while the gateway is stopped is always safe.

Limits: the gateway serves only domains with an empty genesis, and a seeded domain goes `INCONSISTENT` with the reason "the domain's genesis state is not empty; the gateway serves only domains with an empty genesis". Pending batches hold at most 256 MiB of decoded data per domain, and `pending` stops below a batch that would pass it until Settlement accepts batches below. A bundle above 1 GiB is never loaded and stalls its domain at `SYNCING`. A `REMOTE` domain must also fetch a bundle within one 30 s poll turn (below): about 300 MB at 10 MB/s, so a larger bundle stalls its domain at `SYNCING` on a slow upstream. A record whose input data is longer than the longest canonical encoding of its input kind (8,333 bytes for a `CallL2` with an 8 KiB payload, 369 for a `DeployContractStart` with 256 bytes of metadata, 33 for a kind with no tail), whose deploy chunk is longer than 15 KiB, or whose execution result is longer than 32 KiB fails its batch's check and marks the domain `INCONSISTENT`; no executor within Settlement's and the runtime's limits builds one. A bundle's witnesses are bounded only by the 1 GiB ceiling: they never enter the index, but the check decodes every record and witness of the bundle before it counts them, so a hostile 1 GiB bundle needs several GiB of memory. Every `znnd` read has a 30 s deadline and each domain's turn waits at most 30 s on `znnd` reads, so a hung read delays the other domains by at most 30 s per round but never stops them, and the next turn retries. A turn that publishes nothing logs its error once. A turn cut off after publishing a batch logs `the poll used its whole 30s slice; resuming next round` once, until a turn completes. A node that answers some reads and hangs others (a re-read during finalization, say) stays at that one line while every round waits out the full 30 s; its sign is a `finalized` tag that stops advancing while `latest` advances. A local file read that blocks inside the kernel (a hung network or FUSE filesystem under `executorStoragePath` or `storagePath`) still stalls every domain.
